# site/: www.konjir.com

The marketing site at `https://www.konjir.com` (D81), with a section for each product (`docs/plans/rebrand-and-site.md`). It is canonical by the pages' canonical links; `konjir.com` serves the same pages (below). Its source is here, in `site/src/<section>/` (D92, Lee's ruling of 2026-10-23):

| Page | Source |
| --- | --- |
| `/`, the org page | `src/www/main.html`: the page's `<main>`, written as an artboard's is (inline styles, nothing the build refuses): what Konjir is, a card for each product, and which one you need, until the org page has an artboard of its own |
| `/kolab/`, Kolab's page | `src/kolab/project/Main.dc.html`, the artboard, on the claude.ai design runtime, with each image it names as `/_blob/<id>` in `src/kolab/images/<id>.<ext>` |
| `/kolab/how-it-works/`, how Kolab works, for someone new to it | `src/kolab/how-it-works.md`, in the subset of Markdown that `deploy/site/markdown.mjs` renders |
| `/kolab/hands-on/`, the hands-on tutorial | `src/kolab/hands-on.md`, in the subset of Markdown that `deploy/site/markdown.mjs` renders |
| `/konnect/`, konnect's page | `src/konnect/main.html`: the page's `<main>`, written as the org page's is, until konnect has an artboard of its own |
| `/konnect/guide/`, the guide to messages between people and agents | `src/konnect/guide.md`, in the same subset |

`src/www/og.jpg` is the Open Graph image (1200×630, a crop of the brand's reference photograph, first light over a field), which every page names unless its section has its own `src/<section>/og.jpg` (give it alt text in `SECTIONS` in `deploy/site/build.mjs`). konnect's, `src/konnect/og.jpg`, is its name, its line and its install line on the Predawn palette, above the horizon bands.

The tutorial, how it works, the guide and konnect's page live only here. Kolab's artboard and its images are at the paths they have in the claude.ai artifact [Konjir Marketing Page](https://claude.ai/artifact/7CLh2TuhVwCxrFSvyzGw1W), now Kolab's page, which is published from `site/src/kolab/` (below). The artifact holds other files too, its `project/canvas.json` and the design system's tokens (`project/ds/…`): those stay in the artifact, aren't part of the source here, and a publish from `site/src/kolab/` keeps them, since files a publish leaves out are kept. The `konjir-site` kolab (D15) is still the site's future home; until it has W4.1 prototypes to publish from, this is the source.

Everything else here except this README is generated from `src/`, and `terraform apply` publishes it (the `site` module; see *Marketing site* in the top-level README). The module never uploads `src/` or this README. None of `site/` is in Kolab's release, so publishing the site alone doesn't reinstall Kolab.

## Changing a page

1. Edit its source above. In the artboard, images live in `src/kolab/images/` as `<id>.<ext>` and the artboard names each as `/_blob/<id>`, where `<id>` is the 32 hex digits of its id in the artifact's asset store. A new image gets its id by being uploaded there (below). The artboard links to the site's other pages by their full URL on `https://www.konjir.com/…`, which works in the artifact too; the build makes those links relative.
2. Build:

   ```
   node deploy/site/build.mjs
   ```

   With no arguments it reads every source above; `node deploy/site/build.mjs <Main.dc.html> <image-folder>` reads Kolab's artboard and its images from elsewhere. It rewrites `index.html`, `kolab/`, `konnect/`, `404.html`, `robots.txt`, `sitemap.xml`, `favicon.svg`, `og/` and the files in `assets/`, and never touches `src/` or this README. It reads nothing from the network. It keeps the hashed assets that `origin/main`'s pages use (at the merge base with it), and those of every commit since on the branch, so a page cached just before a deploy still finds them and rebuilding a committed build changes nothing; it removes older ones. Without an `origin/main` it keeps HEAD's. CI's *Test on PGlite* rebuilds and fails if anything in `site/` changes or is added, so commit the build with the source.
3. Look at it: serve `site/` (for example `npx http-server site`) and check each page renders, the theme switch works, and the console shows no errors. A plain server serves a folder's `index.html` as CloudFront's function does; it doesn't do the redirects.
4. Commit the source and the build together, in a pull request. Merging it to main starts CI's deploy (D73), which publishes it once its plan and its apply are approved in the `production` GitHub environment. Nobody applies by hand.

A new page is an entry in `PAGES` in `deploy/site/build.mjs` (its path, its section and its source), and its URL in the tests' list (`apps/cli/test/site-build.test.ts`) and in `deploy/terraform/tests/site_files.tftest.hcl`. A new section is an entry in `SECTIONS`, with its header links, and in `PRODUCTS` in `deploy/site/chrome.mjs` if it is a product.

## Publishing each section's artboard to its artifact

Each artifact follows the repository. Only Kolab's page is an artboard today. To publish it after a change, use the Artifact tool's `publish` with `url` the artifact (`https://claude.ai/artifact/7CLh2TuhVwCxrFSvyzGw1W`), `root` `site/src/kolab` and `file_path` the absolute path of `site/src/kolab/project/Main.dc.html`, so the artifact's own paths stay `project/Main.dc.html` and `/_blob/<id>`. A new image is uploaded first, with `publish`, `url` the artifact, `asset: true` and `file_path` the image; name it in the artboard by the `url` the result gives, `/_blob/<id>`, and save it in `src/kolab/images/` as `<id>.<ext>`.

If someone edits the artifact on claude.ai, read it back into `site/src/kolab/` before building, or the next publish overwrites their change: `read` the artifact with `path: "project/Main.dc.html"` and save it over `src/kolab/project/Main.dc.html`, then `read` each new `/_blob/<id>` with `path: "<id>"` and `out_dir` `site/src/kolab/images`. Then build and commit as above.

When the org page and konnect's page become artboards (the plan's steps 3 and 5), each gets an artifact of its own, published the same way with `root` `site/src/www` or `site/src/konnect`, and its source moves to `src/<section>/project/Main.dc.html` with its images in `src/<section>/images/`; its entry in `PAGES` then names it as an `artboard`, and it must use the same helmet (fonts and stylesheet) as Kolab's, since the site has one design.

## What the build changes

The artboard runs on the artifact's design runtime, which a static site can't load. `build.mjs`:

- drops the runtime (`support.js`, `<x-dc>`, `<helmet>`) and the artboard's own `<header>`. Every page gets the one header `deploy/site/chrome.mjs` writes: the Konjir mark, linking to `/`; a product switcher (Kolab, konnect), its section's marked with `aria-current`; the section's own links (on Kolab's page How it works, which leads to `/kolab/how-it-works/`, its in-page links, Roles, For agents and Kolabs, and Try it hands-on; on any other page its section's pages, so an article's links stay within its section); the Daybreak/Predawn theme switch; and on Kolab's pages "Sign in" and "Sign up with GitHub". The section's links, the theme switch and the sign-in are in a `<details>`, the menu, so the header is one row at any width: from 1200px they sit in the row and the menu's summary is hidden; below it the row is the mark, the switcher and the summary, the menu button, and they open in a panel beneath it. The artboard's helmet `<style>` holds the menu's styles (`.hd`, `.menu…`), and its own header, which the artifact shows, is written the same way. The menu opens and closes with no script, and says so as a `<details>` does; site.js keeps it open on a wide screen (read from the stylesheet's `--menu`), and on a narrow one closes it on Escape, a click outside it, focus leaving it or a link in it followed. The theme switch is a radio group: site.js keeps each radio's `aria-checked`, and which is the tab stop, in step with the theme on every page. The theme switch's logic, the artboard's component logic, is in `deploy/site/site.js`: dark by default, then the stored choice (`localStorage` `konjir.theme`) or the system's preference, as the artifact does. site.js also runs the Kolab page's demo of a mark, bound by `data-demo` attributes (its comment says how); the artboard writes the demo in its first state, with its buttons `hidden`, so the page reads whole without the script, as it does in the artifact
- ends Kolab's pages with the artboard's own footer (its in-page links pointing at `/kolab/` from the tutorial), and the other pages and `404.html` with `chrome.mjs`'s, which links to each product's pages. Both end with the same "Source and licences" links, `SOURCE_NAV` in `chrome.mjs`, which the artboard's footer writes word for word (a test holds them equal): the repository on GitHub, `@konjir/kolab` and `@konjir/konnect` on npm, the server's licence (`LICENSE.md`, FSL-1.1-ALv2) and the CLIs' (`apps/cli/LICENSE` and `apps/konnect/LICENSE`, Apache-2.0). There is no privacy policy, terms or contact to link yet
- serves the fonts the artboard links (Fraunces, Instrument Sans and JetBrains Mono, latin and latin-ext) from the copy vendored in `deploy/site/fonts/`, after checking each file against `source.json`, and ships each family's SIL Open Font License beside them, as `assets/fonts/<family>-OFL.txt`. If the artboard's font link changes, the build refuses until you run `node deploy/site/vendor-fonts.mjs '<the new link>'`
- moves every inline `style` into a generated class, so the CSP needs no `'unsafe-inline'`
- names assets by content hash, so they can be cached for a year
- gives every page a viewport tag, a description (the lead paragraph after its `<h1>`, or an article's first paragraph), its canonical URL on `https://www.konjir.com`, Open Graph and Twitter tags (title, description, URL and the image, `og/<section>.jpg`, under a name that doesn't change, so a shared link's preview keeps finding it), and the favicon (`brand/konjir-mark-tile.svg`); writes `sitemap.xml` listing every page, `robots.txt` naming it, and `404.html`, which is `noindex` and names no canonical URL
- renders each Markdown page into its section's header and footer, with a contents list of its `##` headings, and `deploy/site/article.css` added to the shared stylesheet. `markdown.mjs` renders only what these pages use: `#`, `##` and `###` headings, paragraphs, `-` and `1.` lists, tables, fenced code blocks of the kinds `sh`, `text` (a prompt to paste), `output` and `file`, and inline code, bold and links to `https://`, `/` or `#` (holding no `\`, `(` or `)`). It escapes all text, the title included, and refuses anything else, raw HTML included, rather than guess. A heading's id is made from its text, so links to a heading keep working as long as the heading's words don't change. Each finished page is then checked whole: its `<head>` must be exactly the one the build writes, its texts holding no markup and its URLs this site's, and its body must pass the same refusals as the artboard

It refuses, rather than guess, an artboard that uses runtime features it doesn't handle (`<sc-for>`, `<sc-if>`, `<dc-import>`, unknown template holes), whose body isn't one root holding a header, a main and a footer, or anything the CSP would block, in any source: event handler attributes in any case, `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>` or `<form>` in the body, `javascript:` URLs, resources from anywhere but the site itself, and a `style` holding `url()`, `@import` or a brace.

## Where it's served

`https://www.konjir.com` is canonical: every page's canonical link, `og:url` and `sitemap.xml` name it, so search engines consolidate there. `konjir.com` serves the same pages and doesn't redirect. Until this split the site answered www with a 301 to the apex, with no `Cache-Control`, and browsers may keep that for good, so an apex redirected back to www would loop for them. Redirecting the apex is a later, deliberate change, once those have aged out.

On both hosts, the site's CloudFront Function (`deploy/terraform/modules/site/www-redirect.js.tftpl`, tested in `apps/cli/test/site-www-redirect.test.ts`, which also follows the old cached redirect to check nothing loops) answers the pages that moved when the site was split with a 301 to where they are now on www, path below them and query kept: `/hands-on` and `/hands-on/…` to `/kolab/hands-on/…`, and `/messages` and `/messages/…` to `/konnect/guide/…` (from the apex, to `https://www.konjir.com/…` in one hop). Their new URLs never existed before, so no cached redirect leads back. It serves a folder's page from its `index.html`, and sends a folder's path without its slash there. Every 301 it sends may be cached a day (`Cache-Control: public, max-age=86400`), so a later change of direction reaches browsers. A browser keeps a link's `#fragment` through a redirect, so old links to a heading of the tutorial or the guide still land on it. So every link to `https://konjir.com`, `https://konjir.com/hands-on/` or `https://konjir.com/messages/`, the ones published CLIs print and the konnect README on npm included, still works.

The site has no form. People sign up with their GitHub account: "Sign up with GitHub" links to Kolab's sign-in and sign-up, `https://kolab.konjir.com/api/session/oauth/start` (D55), and "Sign in" to `https://kolab.konjir.com/`. Both are plain links, so the CSP needs no other source.
