# site/: www.konjir.com

The marketing site at `https://www.konjir.com` (D81), with a section for each product (`docs/plans/rebrand-and-site.md`). It is canonical, and `konjir.com` redirects to it (below). Its source is here, in `site/src/` (D92, Lee's ruling of 2026-10-23), and nowhere else:

| Page | Source |
| --- | --- |
| `/`, the org page | `src/www/main.html`: the page's `<main>`, its styles inline (nothing the build refuses): what Konjir is, a card for each product, and which one you need |
| `/kolab/`, Kolab's page | `src/kolab/main.html`: the page's `<main>`, written as the org page's is, with the demo of a mark (below). Every Kolab page ends with Kolab's own footer, `src/kolab/footer.html` |
| `/kolab/how-it-works/`, how Kolab works, for someone new to it | `src/kolab/how-it-works.md`, in the subset of Markdown that `deploy/site/markdown.mjs` renders |
| `/kolab/hands-on/`, the hands-on tutorial | `src/kolab/hands-on.md`, in the subset of Markdown that `deploy/site/markdown.mjs` renders |
| `/konnect/`, konnect's page | `src/konnect/main.html`: the page's `<main>`, written as the org page's is |
| `/konnect/guide/`, the guide to messages between people and agents | `src/konnect/guide.md`, in the same subset |

`src/site.css` is the stylesheet every page shares: the Daybreak and Predawn palettes, on the `.kj` root, and the rules for links, buttons (`.kb`), the theme switch (`.tt`) and the header's menu (`.hd`, `.menu…`). The root itself, and the header every page shares, are written by `deploy/site/chrome.mjs`.

`src/www/og.jpg` is the Open Graph image (1200×630, a crop of the brand's reference photograph, first light over a field), which every page names unless its section has its own `src/<section>/og.jpg` (give it alt text in `SECTIONS` in `deploy/site/build.mjs`). konnect's, `src/konnect/og.jpg`, is its name, its line and its install line on the Predawn palette, above the horizon bands.

The `konjir-site` kolab (D15) is still the site's future home; until it has W4.1 prototypes to build from, this is the source.

Everything else here except this README is generated from `src/`, and `terraform apply` publishes it (the `site` module; see *Marketing site* in the top-level README). The module never uploads `src/` or this README. None of `site/` is in Kolab's release, so publishing the site alone doesn't reinstall Kolab.

## Changing a page

1. Edit its source above. A page links to the site's other pages by their path (`/kolab/hands-on/`), so the links work wherever `site/` is served. The build serves no images yet: a page that needs one needs the build to hash it into `assets/` first.
2. Build:

   ```
   node deploy/site/build.mjs
   ```

   It reads every source above, and takes no arguments. It rewrites `index.html`, `kolab/`, `konnect/`, `404.html`, `robots.txt`, `sitemap.xml`, `favicon.svg`, `og/` and the files in `assets/`, and never touches `src/` or this README. It reads nothing from the network. It keeps the hashed assets that `origin/main`'s pages use (at the merge base with it), and those of every commit since on the branch, so a page cached just before a deploy still finds them and rebuilding a committed build changes nothing; it removes older ones. Without an `origin/main` it keeps HEAD's. CI's *Test on PGlite* rebuilds and fails if anything in `site/` changes or is added, so commit the build with the source.
3. Look at it: serve `site/` (for example `npx http-server site`) and check each page renders, the theme switch works, and the console shows no errors. A plain server serves a folder's `index.html` as CloudFront's function does; it doesn't do the redirects.
4. Commit the source and the build together, in a pull request. Merging it to main starts CI's deploy (D73), which publishes it once its plan and its apply are approved in the `production` GitHub environment. Nobody applies by hand.

A new page is an entry in `PAGES` in `deploy/site/build.mjs` (its path, its section and its source), and its URL in the tests' list (`apps/cli/test/site-build.test.ts`) and in `deploy/terraform/tests/site_files.tftest.hcl`. A new section is an entry in `SECTIONS`, with its header links, and in `PRODUCTS` in `deploy/site/chrome.mjs` if it is a product. A section's landing page is its `main` page; give the section a `src/<section>/footer.html` and its pages end with that instead of the shared footer.

## What the build does

`build.mjs` makes static pages that a strict CSP allows, with nothing inline and nothing loaded from elsewhere:

- puts every page in the one root and header `deploy/site/chrome.mjs` writes: the Konjir mark, linking to `/`; a product switcher (Kolab, konnect), its section's marked with `aria-current`; the section's own links (on Kolab's page How it works, which leads to `/kolab/how-it-works/`, its in-page links, Roles, For agents and Kolabs, and Try it hands-on; on any other page its section's pages, so an article's links stay within its section); the Daybreak/Predawn theme switch; and on Kolab's pages "Sign in" and "Sign up with GitHub". The section's links, the theme switch and the sign-in are in a `<details>`, the menu, so the header is one row at any width: from 1200px they sit in the row and the menu's summary is hidden; below it the row is the mark, the switcher and the summary, the menu button, and they open in a panel beneath it. `src/site.css` holds the menu's styles (`.hd`, `.menu…`). The menu opens and closes with no script, and says so as a `<details>` does; site.js keeps it open on a wide screen (read from the stylesheet's `--menu`), and on a narrow one closes it on Escape, a click outside it, focus leaving it or a link in it followed. The theme switch is a radio group: site.js keeps each radio's `aria-checked`, and which is the tab stop, in step with the theme on every page. The theme switch's logic is in `deploy/site/site.js`: dark by default, then the stored choice (`localStorage` `konjir.theme`) or the system's preference. site.js also runs the Kolab page's demo of a mark, bound by `data-demo` attributes (its comment says how); the page writes the demo in its first state, with its buttons `hidden`, so the page reads whole without the script
- ends Kolab's pages with `src/kolab/footer.html` (its in-page links pointing at `/kolab/` from the other Kolab pages; each must name an id on Kolab's page), and the other pages and `404.html` with `chrome.mjs`'s, which links to each product's pages. Both end with the same "Source and licences" links, `SOURCE_NAV` in `chrome.mjs`, which Kolab's footer writes word for word (a test holds them equal): the repository on GitHub, `@konjir/kolab` and `@konjir/konnect` on npm, the server's licence (`LICENSE.md`, FSL-1.1-ALv2) and the CLIs' (`apps/cli/LICENSE` and `apps/konnect/LICENSE`, Apache-2.0). There is no privacy policy, terms or contact to link yet
- serves the fonts (Fraunces, Instrument Sans and JetBrains Mono, latin and latin-ext) from the copy vendored in `deploy/site/fonts/`, after checking each file against `source.json`, and ships each family's SIL Open Font License beside them, as `assets/fonts/<family>-OFL.txt`. To change the fonts, run `node deploy/site/vendor-fonts.mjs '<a fonts.googleapis.com/css2 link>'`
- puts the fonts' `@font-face` rules, `src/site.css`, the classes below and `deploy/site/article.css` into one stylesheet, refusing a `url()` or `@import` in `src/site.css` or `article.css`
- moves every inline `style` into a generated class, so the CSP needs no `'unsafe-inline'`
- names assets by content hash, so they can be cached for a year
- gives every page a viewport tag, a description (the lead paragraph after its `<h1>`, or an article's first paragraph), its canonical URL on `https://www.konjir.com`, Open Graph and Twitter tags (title, description, URL and the image, `og/<section>.jpg`, under a name that doesn't change, so a shared link's preview keeps finding it), and the favicon (`brand/konjir-mark-tile.svg`); writes `sitemap.xml` listing every page, `robots.txt` naming it, and `404.html`, which is `noindex` and names no canonical URL
- renders each Markdown page into its section's header and footer, with a contents list of its `##` headings, and `deploy/site/article.css` added to the shared stylesheet. `markdown.mjs` renders only what these pages use: `#`, `##` and `###` headings, paragraphs, `-` and `1.` lists, tables, fenced code blocks of the kinds `sh`, `text` (a prompt to paste), `output` and `file`, and inline code, bold and links to `https://`, `/` or `#` (holding no `\`, `(` or `)`). It escapes all text, the title included, and refuses anything else, raw HTML included, rather than guess. A heading's id is made from its text, so links to a heading keep working as long as the heading's words don't change. Each finished page is then checked whole: its `<head>` must be exactly the one the build writes, its texts holding no markup and its URLs this site's, and its body must pass the same refusals as its source

It refuses, rather than guess, a `main.html` that isn't one `<main>`, a `footer.html` that isn't one `<footer>`, and in any source anything a static page under the CSP can't have: an element that isn't HTML's or the SVG the pages draw with (a custom element, say), a template hole (`{{…}}`), event handler attributes in any case, `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>` or `<form>` in the body, `javascript:` URLs, resources from anywhere but the site itself, and a `style` holding `url()`, `@import` or a brace.

## Where it's served

`https://www.konjir.com` is canonical: every page's canonical link, `og:url` and `sitemap.xml` name it, so search engines consolidate there. `konjir.com` redirects to it (Lee, 2026-11-20): the site's CloudFront Function (`deploy/terraform/modules/site/www-redirect.js.tftpl`, tested in `apps/cli/test/site-www-redirect.test.ts`) answers every request to the apex with a 301 to `https://www.konjir.com` and the same path and query, a page that moved (below) straight to where it is now, in one hop. The location is built from the fixed www host, never from the request's `Host`, and only a request to exactly `konjir.com` is redirected.

Known consequence: until 2026-11-19 the site answered www with a 301 to the apex, with no `Cache-Control`, and a browser may keep that for good. For a browser that still holds it for a www URL it visited then, `https://www.konjir.com/` above all, that URL now loops (www to the apex by the cached 301, the apex back to www by the function's) until the browser drops the entry. The fix for an affected visitor is to clear the browser's cached data for `konjir.com` and `www.konjir.com`; otherwise it ages out of the cache. URLs that never existed on www before (`/kolab/`, `/konnect/guide/`, …), and the moved pages, aren't affected: the test follows the old cached redirect to show each still lands on its page in at most two redirects, and that the loop is confined to the pages that didn't move.

On www, the function answers the pages that moved when the site was split with a 301 to where they are now, path below them and query kept: `/hands-on` and `/hands-on/…` to `/kolab/hands-on/…`, and `/messages` and `/messages/…` to `/konnect/guide/…`. It serves a folder's page from its `index.html`, and sends a folder's path without its slash there. Every 301 it sends may be cached a day (`Cache-Control: public, max-age=86400`), so a later change of direction reaches browsers. A browser keeps a link's `#fragment` through a redirect, so old links to a heading of the tutorial or the guide still land on it. So every link to `https://konjir.com`, `https://konjir.com/hands-on/` or `https://konjir.com/messages/`, the ones published CLIs print and the konnect README on npm included, still works.

The site has no form. People sign up with their GitHub account: "Sign up with GitHub" links to Kolab's sign-in and sign-up, `https://kolab.konjir.com/api/session/oauth/start` (D55), and "Sign in" to `https://kolab.konjir.com/`. Both are plain links, so the CSP needs no other source.
