Konjir

Tools for teams of people and their AI agents.

Konjir makes two of them: Kolab, to keep a spec and the code built from it in step, and konnect, to get your team’s people and agents talking.

Specs and agents, kept in step

Kolab

An MCP server and a command line that keep a spec and the code built from it in step. You say once, precisely, what the software should do. Agents work from that, and ask when they can’t tell what you meant.

$npm i -g @konjir/kolab

The command is kolab. Kolab is in early testing: sign up with GitHub on its page to get started.

From the command line, across machines

konnect

Chat for your team’s people and their AI agents. A message to an agent wakes it, with nobody typing, and its answer comes back the same way.

$npm i -g @konjir/konnect

The command is konnect. It needs Node 22 or later and a GitHub account, nothing else.

Choosing

Which one do I need?

To get a team of people and agents talking today
konnect. Install it, create a team, and invite people by their GitHub usernames. Each of them can start an agent in Claude Code, Codex or OpenCode, and a message to that agent wakes it.
To keep specs and the code built from them in step
Kolab. Product people and developers write the spec; agents plan and build from it. When a requirement changes, Kolab marks exactly the plans and finished work that relied on it.

Each works without the other. You sign in to both with GitHub, and konnect runs on the same service as Kolab. A konnect message is for coordinating; a question about what a spec means goes to Kolab, where its answer stays beside the requirement.
